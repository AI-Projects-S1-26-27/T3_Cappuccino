==========================================================================
T1. PARTITIONER + MANIFESTS                       [critical path, start now]
==========================================================================
Goal: split the 199 training engines (and the 50 validation engines) across K = 5 clients with a
controllable amount of label skew H, and freeze every split to a file.

Where: src/rulfl/partition/__init__.py (+ a script to write manifests), tests/test_partition.py

Build:
  1. assign_clients(lifetimes: dict[int,int], K: int, H: float, seed: int) -> dict[int,int]
       - Sort engines by (lifetime, engine id) (PT2), cut into K contiguous blocks as equal as possible
         (199 -> 40,40,40,40,39).
       - Engine in block b goes to client b with probability H, otherwise to a uniformly random client
         (P(client k) = H*1[b=k] + (1-H)/K). Randomness from np.random.default_rng(seed) (PT3).
       - If any client ends with < cfg.partition.min_engines_per_client (10) engines -> raise. NO redraws (PT4).
  2. skew(labels_by_client: list[np.ndarray], all_labels: np.ndarray) -> float
       - Mean over clients of Wasserstein-1 distance (in cycles) between that client's training RUL labels
         and all training labels (PT6). numpy only (no scipy) - W1 between two 1-D empirical
         distributions = integral of |CDF_a - CDF_b|.
  3. Validation routing (PT5): route the 50 validation engines with the SAME rule, H and seed, using their
     own lifetime blocks (ds.val_engine_lifetimes).
  4. Manifest writer (PT7): for every H in partition.H_grid x every seed in seeds.main + seeds.selection +
     seeds.pilot, write manifests/H{H:.2f}_s{seed}.json with
       {"train": {engine: client}, "val": {engine: client}, "sha256": "...", "H":..., "seed":..., "skew":...}
     The keys "train"/"val" are REQUIRED - run_federated already reads that format (DECISIONS line ~132).
     Commit the manifests. Never hand-edit them. Store the hash so runs can record which manifest they used.
Tests (required):
  - H = 1 -> every engine lands in its own block's client.
  - Same (lifetimes, K, H, seed) -> identical result; different seed -> different result (for H < 1).
  - Seed-averaged skew strictly increases over H in {0, .25, .5, .75, 1} (PT6).
  - < 10 engines on a client raises.
  - Block sizes 40,40,40,40,39 for 199 engines.
  - Manifest loads into run_federated without error (small smoke run on the test slice).
Done when: manifests/ committed, tests green, skew-vs-H table pasted into the PR description.


==========================================================================
T2. EVALUATION METRICS + STATISTICS               [start now, no dependency]
==========================================================================
Goal: every number in the report comes from these functions.

Where: src/rulfl/eval/__init__.py (split into metrics.py / stats.py if it grows), tests/test_eval.py

Build:
  1. nasa_score(pred, true) -> float  (E1): d = pred - true; cost = exp(d/10)-1 if d >= 0 (late),
     exp(-d/13)-1 if d < 0 (early); summed over engines.
  2. metrics(pred, true) -> {"mae", "rmse", "nasa"}  (E1). Inputs are already clamped predictions (M4) and
     capped labels (D8).
  3. life_stage_mae(pred, true, edges=(50,125)) -> {"near": .., "mid": .., "healthy": ..}  (E4).
     On real FD004 test labels the counts must be 79 / 102 / 67 - assert this in a test.
  4. worst_client_mae(client_val_mae_at_best_round) -> max, ignoring nan (E2).
  5. rounds_to_threshold(val_mae_per_round, centralized_best_maes, threshold=1.10) -> int | None  (E3)
     None = "not reached" (censored). Never drop such runs.
  6. Paired stats (E7), numpy only:
       - paired_diff_bootstrap_ci(a, b, n_boot, seed) -> (mean_diff, lo, hi), 95%
       - wilcoxon_signed_rank_exact_one_sided(diffs) -> p   (exact by enumerating all 2^n sign flips;
         with n = 5 the smallest p must be 1/32 = 0.03125 - test this; pooled H >= 0.5 uses n = 15)
Tests: hand-computed examples for every function; NASA score asymmetric (late costs more than early);
       Wilcoxon p matches scipy.stats.wilcoxon on a few vectors (scipy may be used in the TEST only if it is
       already installed; otherwise hard-code expected values).
Done when: all functions + tests merged.

T3. EXPERIMENT RUNNER + RUN ARTIFACTS             [start now; uses T1/T2 when ready]
==========================================================================
Goal: one command runs one registered experiment and saves everything needed to regenerate any number
later (E8). All later tasks (T4, T6, T7, T8, T9) run through this.

Where: src/rulfl/run.py (or scripts/run.py), tests/test_run.py

Build:
  1. CLI, e.g.  python -m rulfl.run --kind {centralized,local,federated} --algo {fedavg,fedprox,fedla}
                 --H 0.5 --seed 1 [--engine sim|flower] [--set fl.mu=0.01 ...]
  2. Sets torch threads = 3 and torch.use_deterministic_algorithms(True) (M5) before anything else.
  3. Output folder runs/<kind>_<algo>_H<H>_s<seed>/ containing:
       config.yaml (the fully resolved config), manifest sha256, per-round log (CSV/JSON: val_mae,
       client_val_mae, bytes), final metrics (test mae/rmse/nasa, worst-client MAE, rounds-to-110%,
       life-stage MAE), best checkpoint (.pt), test predictions (.npy or .csv: engine, pred, true, true_uncapped),
       git commit hash, wall-clock time.
  4. Skip a run whose folder already has a "DONE" marker (so the grid can be resumed after a crash).
  5. A batch script that launches a list of runs in parallel processes (laptop: ~3-4 processes x 3 threads).
  6. runs/ goes in .gitignore except a small results index (one CSV row per finished run) that IS committed.
Tests: a tiny federated run (2 rounds, test slice) produces every file above; rerunning it is skipped.

  2. Grid: hidden {32,64,128} x layers {1,2} x lr {0.001,0.003} = 12 configs, seed 1, train_centralized,

     slow, raise it with the group now (M5: then ALL runs move to GPU together, never mixed).

     seed=client_seed(run_seed, server_round, client_id), sample_weight=...). Arms:

     (val_mae, client_val_mae, bytes, best_round, best_state). Plug into the T3 runner as --engine flower.
  4. GATE 2 test: for fedavg, fedprox and fedla, a short run on the test slice gives identical per-round
     val MAE (to ~1e-6), identical best_round and identical final weights in Flower vs run_federated.
